# プロダクト概要と MVP

## qool とは

**画像や図形を組み合わせて作る、Mac 上のメモアプリ**です。

macOS 標準のメモ / 付箋のように「思いついたときにすぐ開いて、書いて、閉じる」使い方を目指しつつ、
中身は単なるテキストではなく、**キャンバス上に図形・切り抜き画像・テキストを自由に配置したもの**になります。

## MVP のゴール

MVP は次の 3 つが揃った状態と定義します。

1. **画像と図形を組み合わせてメモを作れる**
   - 矩形 / パス / 直線 / テキストをキャンバスに置ける
   - 図形同士を結合 (Union) して任意形状を作れる
   - 写真から必要な部分だけを切り抜いてメモに貼れる
2. **作ったメモを Mac 上で使える**
   - デスクトップ上に、メモとして常時参照できる形で表示できる
3. **特定のキーバインドで呼び出せる**
   - グローバルホットキーで、他のアプリを使っている最中でも即座に呼び出し／退避できる
   - `⌃Q → F` でメインのメモをトグル表示（[キーバインド設計](hotkeys.md)）
   - **キーの組み合わせはユーザーが自由に設定できる**（[詳細](hotkeys.md#グローバルホットキーとは)）

「作る」だけでなく **「日常の中で呼び出して使える」ところまでが MVP** です。
逆に言うと、作成機能がどれだけ充実しても、呼び出せなければ MVP は達成されません。

## MVP のスコープ外（将来検討）

現時点では扱いません。設計時に将来の余地だけ残しておきます。

- Markdown の記述・表示
- PDF への書き出し
- 同期 / 共有 / マルチデバイス

## 決定が必要な事項

### 【決定】プラットフォーム: macOS 専用

**qool は macOS 専用アプリとして作り直します。** iOS / iPadOS には対応しません。

現在の qool は iOS / iPadOS アプリとして作られています。

- `SDKROOT = iphoneos`、`TARGETED_DEVICE_FAMILY = "1,2"`（iPhone + iPad）
- Mac Catalyst / macOS ターゲットは未設定
- [`CanvasSurface`](../../Presentation/Views/Components/CanvasSurface.swift) と
  [`CanvasPropertiesPanel`](../../Presentation/Views/Components/CanvasPropertiesPanel.swift) が `UIKit` に依存
- `CanvasSurface` は Shift キー検出に `GameController` / `UIPress` を使用

一方 MVP は「Mac 上で使えるメモ」「キーバインドで呼び出す」であり、**macOS が主戦場**です。
また取り込み予定の [StarWindow](../image-editing/README.md) は最初から macOS / AppKit で書かれています。

したがって **qool は macOS 専用アプリとして作り直します。**
マルチプラットフォーム化は考えません。この資料群はその前提で書かれています。

影響:

- 上記 2 ファイルの `UIKit` 依存は AppKit へ置き換え（あるいは共通化）が必要
- ツールドックの `GlassEffectContainer` / `glassEffect` は macOS でも使えるが、
  そもそもタッチ前提の下部ドック UI は Mac では設計から見直す対象
- 逆に、StarWindow の AppKit 実装（フローティングウィンドウ、`NSEvent` モニタ、`NSTextView` の
  `exclusionPaths`）は**書き換えずにそのまま活かせる**

### 【決定】Vision はモダン API を使う

輪郭抽出に使う Vision は、`VN` 接頭辞の旧 API ではなく
**macOS 15 以降の Swift ネイティブ API（`async` ベースのリクエスト型）を使います。**

- 移植元の [StarWindow](../image-editing/README.md) は旧 API で書かれているため、**ここは書き換えになります**
- ロジック（どのリクエストをどう使い、結果をどう正規化座標へ変換するか）はそのまま流用できます
- これに伴い、macOS デプロイメントターゲットは 15 以上が必要です

### 【決定】デプロイメントターゲット: macOS 26 以上

UI に **Liquid Glass**（`.glassEffect(in:)` / `GlassEffectContainer`）を採用すると決めたため、
**macOS 26 以上**が最低要件になります（[理由](../design/screens.md#マテリアルliquid-glass)）。

- Vision のモダン API（15 以上）の要件も当然満たします
- 既存の [`CanvasToolDock`](../../Presentation/Views/Components/CanvasToolDock.swift) が使っている
  `glassEffect` の考え方は、そのまま macOS に持ち込めます

## ホットキーで呼び出したときの挙動

> キーバインドの体系・実装方式・未確定事項は [hotkeys.md](hotkeys.md) にまとめています。

**描画については確定しています。** [StarWindow](../image-editing/README.md) と同じく、
AppKit の borderless / 透明 / floating な `NSWindow` に、輪郭でマスクした内容を描いたものが出ます
（[4.8](../image-editing/04-integration-plan.md#48-mvp-のコアとして移植するもの)）。

### 【決定】呼び出しの体系

**`⌃Q` をプレフィックスとし、続けて押したキーで操作を決めます。**

```text
⌃Q → F    メインのメモを表示 / 非表示（トグル）
⌃Q → N    新しいメモを作る
```

初期設定であり、プレフィックスも各操作のキーもユーザーが変更できます。

| 論点 | 決定 |
|------|------|
| 何が出るか | **メインのメモ 1 枚** |
| もう一度押したら | **隠す（トグル）** |
| 出る位置・サイズ | **前回の状態を復元する** |

### 未確定

| 論点 | 内容 |
|------|------|
| 「メイン」の決め方 | ユーザーが指定 / 直近に編集したメモ / 固定の 1 枚（[比較](hotkeys.md#未確定-メインとは何か)） |
| メイン以外のメモの呼び出し | MVP では不要。将来どう扱うか |
| 同時表示できる枚数 | MVP では 1 枚。複数並べられるようにするか |
| プレフィックスの初期値 | `⌃Q` はターミナルのフロー制御と衝突する（[注意](hotkeys.md#q-を選ぶときの注意)） |

## 開発方針

**クラッシュアンドビルド。**

現在の qool の UI・パラメータは検証段階のものであり、作り直す前提で扱います。
そのため以下は**現時点では問題として扱いません**。

- qool と StarWindow でスライダーの範囲や既定値が食い違っていること
- 現在の画面レイアウト（iPhone 幅ではプロパティパネルが出ない等）の作り込み不足
- 現在の画像ワークフローがモックであること

StarWindow 側も同様に「製品版は一から作り直す」前提の検証コードです。
**両方から残すべきなのは「動くコード」ではなく「動くと分かったアルゴリズムと UI の設計判断」**です。

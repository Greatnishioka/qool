# 画面リスト

**ステータス: UI デザイン着手用の初版。** 現在の iOS 実装（[features/](../features/README.md)）は参照せず、
[MVP](../product/mvp.md) と [キーバインド設計](../product/hotkeys.md)から引き直したものです。

> **モックアップ**: この画面リストを Claude Design プロジェクト
> 「qool — macOS メモアプリ」に起こしてあります。
> ローカルのソースは [mockups/](mockups/) にあり、そこから同期しています。

## デザイン原則

1. **Apple 純正コンポーネントをそのまま使う**
   独自コントロールを作らない。`List` / `Slider` / `Picker` / `ColorPicker` / `Toolbar` /
   `Inspector` / `Settings` / `NSVisualEffectView`（`.regularMaterial`）で構成する
2. **小さく、最小限**
   常時目に入るものほど小さく。ウィンドウのクロームを増やさない
3. **小さいが情報は詰め込む**
   Apple Music のミニプレーヤーが基準。**幅 320pt に、アートワーク + 2 行テキスト +
   操作ボタンを 1 行に収める**密度を目標にする

### マテリアル（Liquid Glass）

**面の上に重なるものは、すべて Liquid Glass（`.glassEffect(in:)`）で浮かせます。**
これに伴い[デプロイメントターゲットは macOS 26 以上](../product/mvp.md#決定デプロイメントターゲット-macos-26-以上)です。

透ける半透明には 2 種類あり、使い分けが要ります。

| ブレンド | 透けるもの | 使う場面 |
|----------|-----------|----------|
| `.behindWindow` | **ウィンドウの背後**（デスクトップ、他アプリ） | S2 / S3 のフローティングパネル |
| `.withinWindow` | **同じウィンドウ内の、後ろにある内容** | **S5 / S7 の浮くインスペクタ** |

SwiftUI の `Material` と `.glassEffect` は within-window です。
`ZStack` でキャンバスの上に重ねるだけで、**背後のグリッドと図形が透けます。**

Apple 純正の前例: **フリーボード**（キャンバス上に浮くパレット）、
**マップ**（地図上に浮くサイドバー）、**フォントパネル / カラーパネル**。

#### iOS と macOS で同じものが使えます

`.glassEffect(in:)` / `GlassEffectContainer` / `glassEffectID` / `.buttonStyle(.glass)` は
**macOS 26 でも同じ API** です。iOS で見る Liquid Glass と同じ表現ができます。

差があるのは Apple 自身の適用範囲です。iOS はタブバー・ナビゲーションバー・シートまで広く
当てているのに対し、macOS はサイドバー・ツールバー・メニュー・コントロールに絞っていて控えめです。
ただしこれは「できない」ではなく方針の違いなので、**キャンバスの上に浮くレイヤーに使うのは
HIG に沿った使い方**です。

守るべき制約:

- **ガラスの上にガラスを重ねない**
- **コンテンツ自体をガラスにしない**。浮いているレイヤーにだけ使う
- 背後が濃いとコントラストが落ちる。密度の高い面はより濃いマテリアルを選ぶ

#### モックアップの限界

[mockups/](mockups/) は HTML なので、CSS の `backdrop-filter` で表現できる
「ぼかし + 彩度」までしか再現できていません。**本物の Liquid Glass は以下を行います。**

- 縁のレンズ効果（背後が歪んで縮む屈折）
- 背後の内容と動きに反応するスペキュラハイライト
- 背後の明暗に応じた自動的な濃さの調整
- `.interactive()` によるポインタ追従の変形

**最終的な見た目の評価は、SwiftUI の小さな検証アプリで実物を見て行ってください。**
モックはレイアウトと情報密度を決めるためのものです。

### ミニプレーヤーから引き継ぐ具体的な仕様

参照した Apple Music のミニプレーヤーから、寸法と構造の基準を取ります。

| 要素 | 基準 |
|------|------|
| パネル幅 | **320pt 前後** |
| 角丸 | 大きめ（12〜16pt）。フローティングパネルらしさ |
| 背景 | `.regularMaterial`（背後が透ける） |
| リスト行 | **高さ 44〜48pt**。左にサムネイル 40pt 角、右に `...` メニュー |
| 行のテキスト | **2 行**。1 行目にタイトル、2 行目に副次情報（`—` 区切りで 2 要素） |
| セクション見出し | 太字 + その下に補足行。右端にアクション（「消去」相当） |
| モード切替 | セグメンテッドな 2 択ボタンを横並び |
| 省略 | 収まらないテキストは末尾を `…` で切る。**折り返さない** |

## S1. メニューバー項目

常駐の入り口。**qool は Dock ではなくメニューバーに常駐する**前提です。

- `NSStatusItem` にアイコンのみ
- クリックで S3（メモパネル）を開閉
- 右クリック / 長押しでメニュー（新規メモ / 設定 / 終了）

Dock アイコンを出さないことで「思いついた瞬間に開く」常駐ツールの位置づけを明確にします。

## S2. コマンド HUD

`⌃Q` を押した直後に出る、**次のキーを待ち受けるパネル**です。
[プレフィックス方式の 2 打目を権限なしで受け取る](../product/hotkeys.md#2-打目をどう受け取るか)ための実体でもあります。

- 画面中央に小さく浮かぶ。`.regularMaterial` + 大きめ角丸
- 割り当て一覧を**キーと操作名の 2 列**で並べる（`F  メインのメモ` / `N  新しいメモ`）
- 1〜2 秒で自動的に閉じる。`Esc` でキャンセル
- **押せば消えるものなので、最も小さく作る**

Apple 純正では Spotlight や音量 HUD が近い見た目です。

## S3. メモパネル（ホーム）

**ミニプレーヤーに最も近い画面。** アプリの中心です。

```text
┌──────────────────────────────┐  320pt
│  [検索フィールド]         [+] │  ← Toolbar 相当
├──────────────────────────────┤
│  ┌────┐                      │
│  │ ▣  │  メインのメモ         │  ← 現在メインのメモを大きめに
│  └────┘  12 オブジェクト  ⌃Q F│
├──────────────────────────────┤
│  最近使った項目          消去 │  ← セクション見出し + アクション
├──────────────────────────────┤
│  ┌──┐ 買い物メモ         ⋯  │  ← 44pt 行
│  │▣ │ 3 オブジェクト — 昨日   │
│  └──┘                        │
│  ┌──┐ 会議のスケッチ      ⋯  │
│  │▣ │ 8 オブジェクト — 3日前  │
│  └──┘                        │
│         …                     │
└──────────────────────────────┘
```

- **行の情報量**: サムネイル（キャンバスの縮小描画）+ タイトル + 「N オブジェクト — 更新日時」
- サムネイルは**実際のキャンバス内容を描く**（ミニプレーヤーのアートワークに相当）
- 各行の `...` メニュー: メインに設定 / 複製 / 書き出し / 削除
- 上部に**現在メインのメモ**を固定表示し、割り当てキーを添える
- 使うのは `List`（`.inset` スタイル）、`Toolbar`、`.searchable`

行をクリック → S5（キャンバス編集ウィンドウ）を開く。
**iOS 実装のような画面遷移（push）はしません。** 別ウィンドウで開きます。

## S4. フローティングメモ

`⌃Q → F` で出てくる、**任意形状のメモ本体**です。

- borderless / 透明 / floating な `NSWindow`
- 輪郭でマスクされ、**外側のクリックは背面のアプリに抜ける**
- タイトルバーなし。ドラッグで移動できる
- ホバー時のみ、最小限の操作（編集 / 閉じる）を隅に薄く出す
- もう一度 `⌃Q → F` で消える

**クロームをゼロにする**のがこの画面の要点です。メモそのものだけが浮いて見える状態を目指します。

## S5. キャンバス編集

メモを作る・編集するウィンドウ。**編集には面積が要る**ため、一覧系より大きくなります。
その代わり、クロームは最小限にします。

- 標準の `Toolbar` にツール（選択 / 矩形 / パス / 直線 / テキスト / 画像）を置く
  → **iOS 実装の下部フローティングドックは使いません**。macOS ではツールバーが純正の作法です
- キャンバスは**ウィンドウ全面**。白 + グリッド
- プロパティは右上に**浮かせる**。幅 244pt、Liquid Glass。背後のグリッドと図形が透ける

### `.inspector()` は使いません

SwiftUI の `Inspector` は**ドッキングされた区画**なので、浮かせる用途には使えません。
`ZStack` でキャンバスの上に重ね、`.glassEffect(in:)` を当てます。

これにより、標準で付いてくる以下を**自前で実装する**ことになります。

- 折りたたみ / 展開
- 幅のリサイズ
- ツールバーのトグルボタンとの連携

### 覆い対策: 畳める

浮かせると**パネルの下にある図形に触れません**。対策として、
**ツールバーのボタンとパネル右上のシェブロンで折りたためる**ようにします
（フリーボードのパレットと同じ挙動）。

将来はドラッグでの移動も検討しますが、MVP では畳めることを優先します。

## S6. 画像切り抜き（シート）

S5 から開くシート。画像を読み込み、外周をなぞり、輪郭候補を選ぶ画面です。

- 上部にプレビュー（画像 + なぞり線 + 候補の輪郭）
- **下部に候補選択バー**。スコア付きのチップを横スクロールで並べる
  （★ = 推奨。[候補選択](../image-editing/01-cutout-flow.md#5-候補を選び直す)）
- 操作は `Toolbar` に集約: 画像を選択 / なぞる / 抽出 / リセット / 次へ

## S7. 画像調整（シート）

切り抜いた結果を整えるシート。**qool で最もコントロールが多い画面**です。

- プレビューが全面。コントロールは S5 と同じく**右上に浮かせる**（幅 252pt、Liquid Glass）
- コントロールは `Slider` / `Picker`（セグメンテッド）/ `Toggle` のみで構成
- **モードに応じて出し分ける**（[整理が必要](../image-editing/04-integration-plan.md#45-ui)）。
  常時 15 個以上を並べない
- **S5 より濃いマテリアル**（`.thickMaterial` 相当）を想定。
  コントロールが多く、背後の画像が濃いと可読性が落ちるため

## S8. 設定

`Settings` シーン（純正のタブ付き設定ウィンドウ）。

| タブ | 内容 |
|------|------|
| 一般 | 起動時の挙動、メインのメモの決め方 |
| キーバインド | プレフィックスの変更、各操作の割り当て（[要件](../product/hotkeys.md#要件)） |
| 表示 | フローティングメモの既定の不透明度など |

キー記録 UI は自作になります（[理由](../product/hotkeys.md#ライブラリ選定への影響)）が、
**見た目は純正のショートカット設定に寄せます**。

## 画面遷移

```text
メニューバー (S1) ──クリック──┐
                              ├─→ メモパネル (S3) ──行を選択──→ キャンバス編集 (S5)
⌃Q (S2 コマンド HUD) ─────────┘                                  │
   ├─ F → フローティングメモ (S4) をトグル                        ├─ 画像を追加 → 切り抜き (S6)
   └─ N → キャンバス編集 (S5) を新規で開く                        │        └─ 次へ → 調整 (S7)
                                                                 └─ 閉じる → 保存して S3 へ戻る
```

## 検討事項

- **S3 と S4 の関係**: メモパネルからメモを「浮かせる」操作をどう表現するか
  （行の `...` から「デスクトップに出す」など）
- **S4 を複数出せるか**: [MVP では 1 枚](../product/hotkeys.md#未確定-メイン以外のメモ)。
  複数対応する場合、S3 で「浮いている状態」を示す必要がある
- **S6 と S7 を 1 枚にまとめるか**: 連続した作業なので、シートを 2 段重ねるより
  1 枚の中で段階を切り替えるほうが「最小限」に近い可能性がある
